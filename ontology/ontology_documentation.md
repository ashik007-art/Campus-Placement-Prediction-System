# Campus Placement Ontology Documentation

## 1. Overview and Specification
The **Campus Placement Prediction and Readiness Ontology** is a formal OWL/RDF knowledge representation created to model academic profiles, technical skills, corporate recruiters, job roles, recruitment drives, placement readiness predictions, and recommendations.

- **Namespace URI:** `https://example.org/campus-placement-ontology#`
- **Default Prefix:** `cpo:`
- **Format:** RDF/Turtle (`.ttl`), serialized and compliant with W3C RDF and OWL 2 specifications.
- **Protégé Compatibility:** Validated with W3C standards; can be directly loaded into Stanford Protégé (version 5.5+) or queried using SPARQL 1.1 compliant triplestores (e.g., Apache Jena, GraphDB, RDFLib).

> [!NOTE]
> This ontology formalizes domain concepts and knowledge relationships. Predictive readiness scores and classification in this application are generated by the dedicated Scikit-learn machine learning pipeline and transparent heuristic engine, rather than OWL reasoners.

### Class Definitions
1. **`cpo:Person`**: Base class representing human actors within the academic system.
2. **`cpo:Student`** (`subClassOf Person`): A student candidate participating in training and placement activities.
3. **`cpo:Admin`** (`subClassOf Person`): System administrator managing access, data validation, and institutional metrics.
4. **`cpo:PlacementOfficer`** (`subClassOf Person`): Faculty coordinator conducting campus drives and liaising with recruiters.
5. **`cpo:AcademicInformation`**: Academic performance metrics including CGPA, board percentages, backlogs, and attendance.
6. **`cpo:Skill`**: General capability possessed by students or required for job positions.
7. **`cpo:TechnicalSkill`** (`subClassOf Skill`): Engineering competencies such as Cloud Computing, Machine Learning, or Web Development.
8. **`cpo:ProgrammingSkill`** (`subClassOf TechnicalSkill`): Executable coding proficiencies (e.g., Python, Java, C++).
9. **`cpo:SoftSkill`** (`subClassOf Skill`): Non-technical interpersonal competencies.
10. **`cpo:CommunicationSkill`** (`subClassOf SoftSkill`): Verbal presentation, interview readiness, and written communication.
11. **`cpo:AptitudeSkill`** (`subClassOf SoftSkill`): Analytical, logical, and numerical problem-solving aptitude.
12. **`cpo:Internship`**: Practical industry apprenticeship completed by a candidate.
13. **`cpo:Project`**: Real-world academic or personal project demonstrating applied engineering.
14. **`cpo:Certification`**: Credential certified by an external authority (e.g., AWS, Oracle).
15. **`cpo:Company`**: Corporate partner recruiting talent.
16. **`cpo:JobRole`**: Concrete career opening with defined remuneration and expectations.
17. **`cpo:PlacementDrive`**: Campus drive session scheduled for student applications.
18. **`cpo:EligibilityCriteria`**: Minimum academic and backlog criteria required to register for a drive.
19. **`cpo:Application`**: Student registration submission for a drive.
20. **`cpo:PlacementResult`**: Official selection outcome (Selected, Shortlisted, Rejected).
21. **`cpo:Prediction`**: Assessment indicating placement readiness score and tier.
22. **`cpo:Recommendation`**: Tailored action items to bridge detected skill or academic deficits.
23. **`cpo:Course`**: Academic or industrial training module recommended to elevate readiness.

## 3. Object Properties

| Object Property | Domain | Range | Semantic Meaning |
|---|---|---|---|
| `cpo:hasAcademicInformation` | `cpo:Student` | `cpo:AcademicInformation` | Connects a student to their academic score record. |
| `cpo:hasSkill` | `cpo:Student` | `cpo:Skill` | Links student to mastered skills. |
| `cpo:hasInternship` | `cpo:Student` | `cpo:Internship` | Links student to verified industry internships. |
| `cpo:hasProject` | `cpo:Student` | `cpo:Project` | Links student to executed technical projects. |
| `cpo:hasCertification` | `cpo:Student` | `cpo:Certification` | Connects student to certifications. |
| `cpo:appliesFor` | `cpo:Student` | `cpo:PlacementDrive` | Associates student with applied placement drive. |
| `cpo:conducts` | `cpo:Company` | `cpo:PlacementDrive` | Relates corporate recruiter to recruitment drives. |
| `cpo:offers` | `cpo:Company` | `cpo:JobRole` | Relates company to available job vacancies. |
| `cpo:requiresSkill` | `cpo:JobRole` | `cpo:Skill` | Defines required skills for a role. |
| `cpo:hasEligibilityCriteria` | `cpo:JobRole` | `cpo:EligibilityCriteria` | Links job role to academic criteria. |
| `cpo:hasApplication` | `cpo:PlacementDrive` | `cpo:Application` | Associates drive with received applications. |
| `cpo:hasPlacementResult` | `cpo:Application` | `cpo:PlacementResult` | Relates application to selection outcome. |
| `cpo:receivesPrediction` | `cpo:Student` | `cpo:Prediction` | Links student to calculated readiness assessment. |
| `cpo:receivesRecommendation` | `cpo:Student` | `cpo:Recommendation` | Relates student to actionable recommendations. |
| `cpo:recommendsSkill` | `cpo:Recommendation` | `cpo:Skill` | Suggests specific skills to acquire. |
| `cpo:recommendsCourse` | `cpo:Recommendation` | `cpo:Course` | Recommends relevant courses. |
| `cpo:recommendsJobRole` | `cpo:Recommendation` | `cpo:JobRole` | Recommends compatible target roles. |

## 5. How to Load and Inspect in Protégé
1. Launch **Protégé Desktop**.
2. Select **File > Open...** and navigate to `ontology/campus_placement_ontology.ttl`.
3. Protégé will parse the prefixes, class hierarchy, object properties, and individuals.
4. Navigate to the **Classes** tab to inspect the taxonomy (`Person`, `Student`, `Skill`, etc.).
5. Switch to the **Individuals by class** tab to view sample instances (`Student_PriyaSharma`, `Company_TechCorp`, `Drive_TechCorp2026`).
6. Open the **SPARQL Query** view in Protégé to execute queries from `ontology/ontology_queries.sparql`.
